# csuite — UX audit 001

Audited by driving the running app (Playwright, Chromium, 1440×900 and 1024×768), demo mode end-to-end (play the scripted day, approve + return + reject, resolve the escalation, reports, metrics, EN↔RU) and the live sandbox `?mode=live&company=ux-audit` (one board question, one return → revision, one forced 409, one simulated offline). Judged against `docs/en/CONCEPT.md` (decision is the primary object, CEO attention is protected, disagreements are surfaced, transparency through artifacts) and `web/DESIGN.md`.

Screenshots referenced below live in `…/scratchpad/shots/`.

---

## Executive summary

- **The product's core object is a decision, but the UI has no decision *thread*.** A returned proposal and its revision arrive as two unrelated inbox rows with near-identical titles and the same timestamp (`31-live-r2-arrived.png`); the CEO's own question — the thing that caused the revision — is rendered on neither. The data already carries `revises` and the note; only the UI is missing.
- **"The board's disagreements are shown to the CEO" is true in the data and nearly false in the reading experience.** Disagreements sit at the very bottom of a 4,600-px document (~1,800 words, 6–7 screens). Nothing at the top, in the inbox row, in the badge or in Metrics says "the board is split on 2 points."
- **The demo — the product's sales artifact — ignores a CEO decision.** Rejecting the podcast proposal still creates its tasks, spends $1,200, and files reports saying the test is "underway" (`16-floor-eod.png`, `14-reports.png`, `15-metrics.png`). The one thing the demo must prove (your signature drives the company) is the thing it visibly breaks.
- **Trust states are half-built.** Offline + 409 + unknown-company are detected, but a decision submitted while offline fails *silently* (`35-live-offline-approve.png`), the 409 shows raw server text with internal ids (`33-live-409.png`), and after every board run two of three board members stay "Thinking" forever on the Floor (`27-live-floor-after.png`). A revision run shows no progress indicator at all.
- **The chrome does not yet scale past a demo day.** Flat inbox with a permanent "Earlier today" heading, time-only stamps, no per-document URL, no search or filter, a Floor that is silently clipped at 1024×768, and a live Metrics tab that is ~80 % empty placeholders.

## Critical — blocks comprehension or trust

### UX-1 · A return and its revision are two unrelated documents; there is no thread
**Observed.** Live sandbox, Desk (`28-live-desk-two-pending.png`, `29-live-returned.png`, `31-live-r2-arrived.png`). I returned "Approve one $2,000 newsletter test with **strict conditions**" with the note *"Who owns this test, and what is the exact number that makes us call it a failure and stop?"*. ~50 s later the inbox showed:

| group | row | time | status |
|---|---|---|---|
| Needs you | Approve one $2,000 newsletter test with **two launch gates** | 02:48 | Waiting for your decision |
| Earlier today | Approve one $2,000 newsletter test with **strict conditions** | 02:48 | Returned with questions |

Same author, same minute, two rows, two 10,000-character documents, in two different sections of the list, with titles that differ by three words. The only clue they are one conversation is a sentence buried in paragraph 1 of the revision's Rationale ("What changed from the returned proposal is…"). The older sandbox thread shows the same fracture with titles that differ completely ("Raise new-customer prices 20% with a controlled rollback test" → "Approve a conditional 20% new-customer price test"), so the CEO cannot even *recognise* the pair. The server log has everything needed: `proposal_submitted` with `revises: prop-…-c27aff`, plus the `ceo_decision{decision:"returned", note}` and the originating `question_asked` event. The web app never reads `revises` (verified: the only references in the repo are `packages/contract/types.ts` and `server/src/board/run.ts`).

**Why it matters.** CONCEPT's first claim is that the primary object is a *decision with a lifecycle*, not a chat. A lifecycle that splits into unlinked documents at its most interesting moment — the CEO pushing back and the board answering — is not a lifecycle; it is an inbox of PDFs. It also silently multiplies the CEO's reading load: one discussion, three returns deep, becomes four 1,800-word documents to diff by hand.

**Recommendation — make the thread the object, the document a version of it.**
1. **Group in the reducer, not the view.** Fold `revises` chains into a *decision thread* keyed by the root proposal id. The inbox renders one row per thread; superseded versions never get their own row.
2. **Row anatomy:** title of the newest version + `v3 · you returned it 02:48` as the status line + a small stepper glyph (●●○) showing how many rounds this has taken. Sorting uses the newest version's timestamp; the "Returned with questions" state of the previous version is history *inside* the thread, not a competing row.
3. **Document header becomes a thread rail.** Under the title, a horizontal version rail reading left→right: `Asked 02:46 → v1 submitted 02:48 → you returned 02:48 → v2 submitted 02:49 (you are here)`. Each step is clickable and swaps the body; the newest is the default. This is the whole conversation on one line — exactly the "transparency through artifacts" claim.
4. **Render the CEO's turn as a first-class block between versions**, styled as the red-pencil margin note the design language already implies: *"You returned this at 02:48 — 'Who owns this test, and what is the exact number…'"*. It must appear **on the revision**, at the top, above the summary, not only on the superseded document.
5. **"What changed" as structure, not prose.** The board already writes this (it opens the revision's Rationale); have the server emit it as a `changes: string[]` field and render it as a 3-bullet block directly under the CEO's question, plus a lightweight "compare with v1" toggle that shows the two cost figures, the two stance rows, and which sections changed. A CEO deciding a revision needs *the delta*, not the whole document again.
6. **Re-returns simply extend the rail** (v3, v4). If a thread exceeds ~3 rounds, surface that fact ("3rd round — the board has not closed your question") — it is a real management signal.
7. The originating strategic question becomes the thread's first entry, so "why does this exist" is answerable without the event log.

### UX-2 · The CEO's question is invisible everywhere it matters
**Observed.** The strategic question I typed ("Should we sponsor one $2,000 newsletter issue next month…") is never shown again in any view: not in the composer (cleared on submit, `25-live-deliberating-desk.png`), not on the resulting proposal, not in the inbox, not on the Floor except as a truncated ticker chip. The decision note is shown only under the stamp of the *decided* document (`08-stamp-top.png`, `11-returned.png`) — i.e. on the document the CEO has already finished with — and is absent from the revision that exists solely to answer it (verified by text search of the rendered r2: the note string does not appear).

**Why it matters.** The CEO's own words are the only human contribution in the entire system. Dropping them from the record makes the board's answers look unprompted and makes the CEO unable to check "did they actually answer what I asked?" — which is the whole point of "return with questions".

**Recommendation.** Persist and render the CEO's turns as thread entries (see UX-1.4). Echo the asked question under the composer while the board is deliberating ("You asked: …"), and keep it at the head of the thread afterwards. In the revision, pair each CEO question with the board's answer if the server can be made to emit them paired; otherwise show the question verbatim above "What changed".

### UX-3 · The demo overrides the CEO's decision (rejected work ships anyway)
**Observed.** I rejected "Run a 4-week podcast sponsorship test, $2,400" (`13-rejected-by-key.png`). The day then created its tasks anyway — the Floor's Growth column at 18:00 shows "Record sponsor-read intro/outro with two indie-author podcast hosts" and "Set up promo-code and UTM tracking for the podcast test" in progress (`16-floor-eod.png`); Metrics counts them in 7/9 tasks and books $1,200 of spend (`15-metrics.png`); Reports states "The podcast sponsorship test is underway, two of three tasks started" and Rhea files "Podcast CAC tracking live" (`14-reports.png`). Cause: in `web/src/lib/scenario/day-one.ts` the annual-billing and CDN branches are gated with `when:`, but every `prop-podcast` follow-on event (e133–e151, incl. `budget_spent`) is ungated.

**Why it matters.** Phase 0's entire job is "wow first": convince a stranger that their signature runs a company. This is the one place where the demo demonstrates the opposite, and it does so in three views at once. A first-time viewer who rejects anything learns that the decisions are decorative.

**Recommendation.** Gate the podcast branch on `whenPodcastApproved`, and author a rejection branch of 3–4 events (CFO/Growth acknowledge, no spend, EOD summary line changes) exactly as the annual-billing rejection branch already does. Rule for the scenario file: **every proposal must have both branches authored before it is allowed into the demo**; add a cheap test asserting that no event referencing a proposal's tasks/spend/reports is ungated.

### UX-4 · A decision made while the server is unreachable fails silently
**Observed.** With the API unreachable (fetch to :3001 rejected), the red banner "No connection to the server. Showing the last state received, and retrying." appears — good — but the decision bar stays fully enabled. Clicking **Approve** plays the signature stroke and then… nothing (`34-live-offline.png`, `35-live-offline-approve.png`): the proposal stays "Waiting for your decision", no new message appears, nothing is queued. `live.tsx:decide` routes the failure into the same generic `notice`, which is suppressed while `connection === "offline"`.

**Why it matters.** Signing is the CEO's only irreversible act. A signature that quietly does not happen is worse than a blocked button: the user walks away believing the company was told.

**Recommendation.** While offline: disable the three decision buttons and the Ask button, and replace the keyboard hint with "Reconnecting — you can read, but decisions cannot be recorded." On a failed write while *online*, show the failure **in the decision bar** (where the click happened), in the pencil colour, with a Retry: "Not recorded — the server refused. Retry." Never rely on a system bar 800 px away to report the outcome of a button press.

### UX-5 · The board's working state is not honest — stale "Thinking", and revisions run invisibly
**Observed (a).** After every completed board run, the Floor leaves board members pinned to their last worklog: in the sandbox Marcus and Dana still read "Thinking — Writing an independent position on: 'Shoul…'" long after the proposal landed (`27-live-floor-after.png`); on arrival, before I did anything, Iris and Dana were "Thinking" on a run that had finished minutes earlier (`22-live-floor.png`). Only the role that emits the closing "Board run complete" worklog returns to Idle.
**Observed (b).** During the run, the Floor's node states lag the ticker: all three nodes said "Writing an independent position" while the ticker below already reported "Marcus supports with conditions… Iris supports with conditions… Iris started drafting" (`26-live-floor-deliberating.png`).
**Observed (c).** A **revision** run (triggered by "Return with questions") shows **no** deliberating indicator at all — `deliberating` is set only inside `ask()` in `live.tsx`. After returning a proposal the app goes completely silent for ~50 s (`30-live-revision-running.png`).

**Why it matters.** The Floor is the product's one kinetic surface and its claim to "you can see your company working". If it is permanently half-lit with phantom work, it stops being information and becomes decoration — and "is the board doing anything about my questions?" becomes unanswerable at the exact moment the CEO cares.

**Recommendation.** (a) Derive node activity from the run lifecycle, not from the last worklog: when a board run ends (or after an idle timeout), every participating role returns to Idle. (b) Advance a role to "Position filed" the moment its `position_submitted` event arrives. (c) Treat any in-flight board run as deliberating — set the flag from the event stream (a run started and not yet answered) rather than from the local `ask()` call, and label it: "Revising 'Approve one $2,000 newsletter test' — 2 of 3 positions in · 0:38". Cheap and honest: a counter of positions received and an elapsed timer.

## Major — hurts daily use

### UX-6 · Disagreements are buried at the bottom of a very long document
**Observed.** "Where the board disagrees" is the last section of the proposal: y≈4,028 px of a 4,615-px document in live (`24-live-consulted-disagree.png`), y≈2,500 of 2,710 in demo (`06-desk-bottom.png`). To reach it a CEO scrolls past summary, rationale, alternatives, cost, risks and three full positions. Nothing earlier hints it exists: not the kicker ("Proposal | Waiting for your decision"), not the inbox row, not the Desk badge, not Metrics (which counts escalations but not open disagreements).

**Why it matters.** "Disagreements are recorded and shown to the CEO, not smoothed over" is a headline claim and a genuine differentiator. Reading order decides what is actually seen; today the differentiator is in the footer.

**Recommendation.** Add a **decision brief** band directly under the byline: stance chips (`Supports 1 · With conditions 2 · Objects 0`), the cost, and — when `disagreements.length > 0` — a pencil-coloured line "The board is split on 2 points" that anchor-scrolls to the section. Mirror the count in the inbox row (a small pencil dot + "2 open splits") and add an "Open disagreements" stat tile to Metrics. Consider moving the section above the individual positions entirely: the split is the executive summary of a deliberation; the positions are the appendix.

### UX-7 · "Return with questions" reads as a dead button, and the note is labelled optional
**Observed.** In every screenshot of the decision bar the middle button is 50 % opacity and grey (`03-desk-proposal.png`, `23-live-desk.png`) — it is genuinely disabled until a note is typed (`DecisionBar.tsx`), with the explanation only in a native `title` tooltip. Meanwhile the input next to it says "Add a note for the board **(optional)**" and the hint under it advertises only A and R shortcuts.

**Why it matters.** The revision loop is the product's most distinctive interaction and its affordance is invisible. The copy actively misleads: the note is optional for two of three actions and mandatory for the third.

**Recommendation.** Keep the button enabled; on click with an empty note, focus the input and change its placeholder to "What do you want answered before you sign?" Make the note field's label reactive ("Note for the board" / "Your questions — required to return"). Give returning a keyboard shortcut too, and state all three in the hint.

### UX-8 · "What needs me now" is split across surfaces and does not distinguish urgency
**Observed.** The Desk badge is a single amber count that merges pending proposals and open escalations (`40-topbar-detail.png`). Reports carry their own "Needs from you:" blocks — "Go/no-go on tomorrow's live subscriber migration…" appears in two reports (`14-reports.png`) — which are not counted anywhere, not actionable, and have no route to an answer. The scripted day *pauses* for a routine proposal but **not** for an urgent escalation: the Indie Author Weekly escalation (5 pm deadline, above the growth lead's authority) was raised at 12:25 and sat unseen until the clock stopped at 13:20 for an unrelated proposal (`09-escalation.png`).

**Why it matters.** "The CEO's attention is protected by authority limits" means the system, not the CEO, decides what is urgent. Today the system's own urgency model is inconsistent with its own data.

**Recommendation.** One queue, ranked by authority/urgency: escalations (urgent → attention) above pending proposals, above report asks. The badge should split visually (pencil dot for escalations + count, amber count for signatures). Any *open* escalation must stop the day exactly as an awaiting proposal does. Turn "Needs from you" in a report into a real desk item with a resolve affordance, or drop the phrase — a request with no reply channel is theatre.

### UX-9 · Irreversible decisions: one keystroke, no confirmation, no undo
**Observed.** Pressing `r` with nothing focused rejects the selected proposal instantly — no dialog, no undo, no note (`12-third-proposal.png` → `13-rejected-by-key.png`). The decision bar then disappears entirely. There is no way to revisit or amend a decision anywhere in the app.

**Why it matters.** The metaphor is paper and signature ink; ink is not undoable, which is precisely why real signing has a beat of ceremony. A bare letter key is the opposite of ceremony, and it collides with any future type-ahead/search.

**Recommendation.** Keep A/R as *arming* shortcuts: highlight the target button and require Enter (or a second press) to commit — the design language's "signature stroke" animation is already the right beat; make the commit happen at the end of it and offer "Undo" for those ~2 s. Move raw single keys behind a modifier if they stay at all.

### UX-10 · After deciding, the confirmation happens off-screen and the document is yanked away
**Observed.** I approved from the bottom of the document; the "Approved 09:55" stamp with my quoted note is rendered at the top, four screens up, and the pane does not scroll to it (`07-approved-stamp.png` vs `08-stamp-top.png` after manual scroll). After resolving the escalation and after returning the newsletter proposal, the reading pane swapped itself to the next urgent item within ~1.7 s (`10-escalation-resolved.png`, `29-live-returned.png`), so the outcome of my action was never visible at all.

**Recommendation.** On decide: scroll the pane to the stamp (or float a compact confirmation next to the button — "Approved · note sent to Marcus · Undo"), hold the document until the user leaves it, and let the inbox's *selection* change only on explicit user action or when the item leaves the list.

### UX-11 · Error copy is developer output, and the unknown-company state lies
**Observed.** Forcing a conflict produced, in a system bar at the top of the window: `Proposal "prop-should-we-raise-prices-20-c27aff-r2" is "rejected", not "pending_approval" — no decision can be recorded on it` (`33-live-409.png`). Pointing at a non-existent company shows, simultaneously, a permanent amber "Connecting" dot, a notice `Company "no-such-company" not found`, and a card saying "Connecting to the company — reading the event log… check that the server is running" (`32-live-missing-company.png`) — a wrong diagnosis (the server answered fine), a state that will never resolve, a dismissible notice that would leave the app blank and unexplained, and "Spend this month $0 / $0" in the header.

**Recommendation.** Translate API failures into CEO language at the boundary: "This proposal was already rejected at 02:50 — your approval was not recorded. [Show what happened]". Never print internal ids or snake_case states. Make "not found" a terminal state with a route out: "No company 'no-such-company' on this server. [Switch to demo] [Choose a company]" — and stop the connecting animation.

### UX-12 · The Floor is silently clipped at 1024×768
**Observed.** At 1024×768 the department task lists are cut mid-row, the "Tasks" heading collides with the worklog chips above it, and `main` cannot scroll (`scrollHeight === clientHeight`) — the content is simply unreachable (`17-floor-1024.png`). At 1440×900 the same view has ~200 px of dead space at the bottom.

**Recommendation.** Let the Floor scroll (or scale-to-fit with a zoom control); collapse department task lists to "12 tasks · 5 done" with a disclosure below a height threshold. Whatever the company size, "there is more here" must be visible.

### UX-13 · Nothing is addressable; the decision log cannot be navigated
**Observed.** Selecting an inbox item never changes the URL (`/desk` throughout). A proposal cannot be linked, bookmarked, or reopened after a reload; the "Work in flight" task list is not clickable; reports do not link to the decision that caused them; the Floor's tasks do not link to the proposal. The only navigation in the product is four tabs plus inbox rows.

**Why it matters.** "The company's state is readable from the decision log, roadmap, reports and event log" implies artifacts that can be pointed at. Today the artifact only exists while you are looking at it.

**Recommendation.** `/desk/[proposalId]` (and `/desk/escalation/[id]`) as real routes; link report → decision, decision → tasks, Floor task chip → decision. This is also the prerequisite for the thread rail in UX-1.

### UX-14 · The chrome has no answer for volume
**Observed.** The inbox is a flat two-group list ("Needs you" / "Earlier today") with no search, filter, date grouping, or pagination; the "Earlier today" label is hard-coded regardless of when the item happened; timestamps are `HH:MM` with no date, so items from previous days read as today (the sandbox showed 02:11 and 02:48 items from separate sessions under "Earlier today"). Reports offer department filters only — no unread, no "needs you", no search (`14-reports.png`). At 30 proposals and 200 reports this becomes a scroll with no handles.

**Recommendation.** Group history by day ("Today / Yesterday / Sept 9"), switch to relative or dated stamps beyond today, add a persistent filter row on the desk (Needs you · Threads awaiting the board · Decided · All) and a text search over titles; paginate reports by week with a "needs you" filter first.

### UX-15 · Live mode ships three tabs that cannot mean anything yet
**Observed.** In live mode, Reports is an empty page with department filter chrome and the promise "No reports yet. They arrive as the company works through the day" (`36-live-reports-empty.png`) — but nothing in live can produce a report. Metrics shows Budget $0 with the reassurance "On pace", Tasks 0/0, Open escalations 0, two charts saying "The day hasn't produced data yet" with a degenerate `$1 / $1 / $0` axis (`37-live-metrics.png`). Meanwhile the one number live *does* have — the board's per-run cost, logged as `Board run complete — 9 calls (3 with tools, 17 tool consultations), $0.0056` — is visible only as a truncated chip on the Floor.

**Recommendation.** In live mode, either hide what cannot exist yet or label it honestly ("Departments are not wired up yet — Phase 2"). Give Metrics the data it actually has: deliberations run, cost per deliberation, decision latency, revision rounds, open disagreements. "On pace" against $0 spent and no activity reads as a fake.

### UX-16 · The Play button is dead while the day is waiting on you
**Observed.** When the sim pauses for a decision, the transport button flips back to "Play"; clicking it does nothing (the tick immediately re-pauses) — clock stayed 09:55, label stayed "Play" (`02-demo-floor-running.png`). The only cue is a small amber chip elsewhere in the bar.

**Recommendation.** Replace the button with its true state: a disabled control reading "Waiting for your decision" that links to the Desk (the Floor chip already does this well) — or let Play work by auto-selecting the pending item.

## Minor — polish

- **UX-17 · Escalation documents have no title.** The whole situation is set as a 40-px display-serif H1 running four lines (`09-escalation.png`), and its real deadline ("the slot closes at 5 pm today") is prose, not a field. Give escalations a short title + structured `needs / amount / deadline` fields, and render the deadline as a countdown chip next to the severity.
- **UX-18 · Disagreement participants read as a broken sentence.** With three roles the chip row renders "Iris *against* Marcus *against* Dana" (`24-live-consulted-disagree.png`). Use one connector ("Iris vs Marcus vs Dana") or, better, group by position: `Iris · Dana — CTO/COO own it` / `Marcus — CFO owns it`.
- **UX-19 · Provenance is present but inert.** "Consulted: budget summary, tasks in flight, reports" is 11.5-px grey text with no interaction (`24-live-consulted-disagree.png`); the CEO cannot see *what* the budget summary said. Make each item a hover/expand that shows the queried value, and surface the run cost + call count next to it — that is the honest price tag of the document being read.
- **UX-20 · Status colour drifts between views.** `in_progress` is signature blue on the Desk and Floor but `--color-ink-soft` grey in the Metrics task-flow legend (`15-metrics.png`, `TaskFlowChart.tsx:12`) — DESIGN.md says status colours are semantic only.
- **UX-21 · Decision latency is structurally zero in demo.** Because the sim pauses the clock while awaiting, every decision registers 0 m and the chart is three dots on a 0–10 m axis (`15-metrics.png`). Either measure real wall-clock response time or drop the chart from demo. Also: labels truncate ("Introduce annual bill…"), and precision is inconsistent (`2m`, `1.2m`, `39m` in live).
- **UX-22 · Badge contrast and semantics.** The count badge is white 10-px mono on `--color-hold` (#A87A1F) — about 3.5:1, below AA for small text — and merges two different kinds of demand (see UX-8).
- **UX-23 · Desk layout wastes a column.** At 1440 the document sits centred in the pane, leaving ~185 px of empty paper between the inbox and the sheet (`03-desk-proposal.png`). Either left-align the sheet against the inbox or use the gutter for the thread rail / section navigation proposed in UX-1.
- **UX-24 · The mode switch is unexplained.** "Demo | Live" has no visible label (only an aria group "Data source") and no explanation of what changes; in live mode the top bar still reads the company name from config, so `company=ux-audit` displays as "Brightpage" and is indistinguishable from the owner's real company. Label the control, and show the company id somewhere unambiguous.
- **UX-25 · Board-offline still invites you to ask.** The copy is honest ("questions are recorded but not answered") but the Ask button stays enabled and primary-coloured. Disable it, or relabel to "Record question".

### RU locale in situ

- **UX-26 · The A/R shortcuts cannot be used on a Cyrillic layout.** The handler compares `e.key` to `a`/`r`; on a Russian layout those physical keys emit `ф`/`к`, so the advertised hint "Нажмите A, чтобы согласовать, R — чтобы отклонить" (`39-live-desk-ru.png`) is simply false for the audience the RU locale exists for. Match on `e.code` (`KeyA`/`KeyR`).
- **UX-27 · The demo's substance is untranslated.** RU chrome wraps 100 % English fixture content — proposals, positions, worklog notes, report bodies, role titles, department names (`19-desk-ru.png`, `21-floor-ru.png`). For live agent output that is correct by policy; for the *demo scenario*, which is product-authored copy, it means a Russian first-run reads as an English product with translated buttons. Author an RU scenario (or at least RU titles/summaries) if RU is a real target.
- **UX-28 · Wording and fit.** "Простой" for Idle reads as "downtime/stoppage", not "free" — prefer "Свободен"/"Не занят". "Этаж" for Floor is literal and puzzling as a navigation label. In Metrics the RU legend wraps onto a second line where EN fits one (`20-metrics-ru.png`), and mono numbers plus a spaced unit render as "0  мин" against EN's tight "0m".

## Fix next — top 5

1. **UX-1 + UX-2 — build the decision thread.** Group by `revises`, one inbox row per thread, a version rail in the document header, the CEO's question rendered between versions, and a structured "what changed". This is the product's signature interaction and the data is already there.
2. **UX-3 — gate the demo's podcast branch (and add the rejection path).** The demo must never contradict a CEO decision; add the test that forbids ungated follow-on events.
3. **UX-5 + UX-4 — make board state and write failures honest.** Reset roles to Idle when a run ends, drive "deliberating" (with position count and elapsed time) off the event stream so revisions show progress, and never let a decision fail silently.
4. **UX-6 — promote disagreements.** A decision brief band under the byline with stance counts and "the board is split on N points", mirrored in the inbox row and in Metrics.
5. **UX-7 + UX-9 + UX-10 — fix the act of deciding.** Enable "Return with questions" with reactive copy, make A/R arm rather than commit with a brief undo, and land the confirmation where the user clicked instead of four screens away.
